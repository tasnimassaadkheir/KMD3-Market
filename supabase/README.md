# Edge Function `admin-usuarios`

Lets the **Administração** screen create users, cancel / reactivate them and set temporary
passwords, without opening Supabase. It runs **inside Supabase**, because creating a login needs
the project's secret key, which must never go to the browser.

| File | What it is |
|---|---|
| `functions/admin-usuarios/index.ts` | Entry point (Deno): creates the Supabase clients and calls the logic |
| `functions/admin-usuarios/logica.mjs` | All the logic (checks, create, cancel, reactivate, new password, e-mail). Tested in `tests/unit/admin-usuarios.test.js` |
| `functions/admin-usuarios/para-colar.ts` | The two files above in **one** file, for pasting into Supabase's web editor. Generated by `node scripts/funcao-colar.mjs` (a test fails if it's out of date) |

## What it does and who may do it

Every request is checked **with the permissions of the person who clicked** (their login token):

1. They must be a **super-admin** (any organization) or an **admin of that organization**
   (`sou_super`, `sou_admin`, `admin_organizacoes`). Only the super-admin creates organizations,
   and cancels or resets the password of another admin. Nobody can cancel their own access.
2. **Criar usuário**: creates a confirmed login with the password typed in the screen, marked
   *trocar_senha*. Then it adds the person to the organization with `adicionar_membro`, as the admin,
   so the database's own rules apply. If that fails, the new login is deleted again, so no orphan
   logins are left. If the e-mail already has a login, it's only added to the organization, its
   password isn't changed and no e-mail is sent.
3. **Cancelar acesso**: blocks the login (Supabase *ban*), so the person can't log in anymore, and
   marks the member inactive. Their condos, notes and history stay. **Reativar** undoes it. An
   already open session stops working when its token expires (up to 1 hour).
4. **Nova senha**: sets a new temporary password (*trocar_senha* again).
5. **E-mail**: sends the address, e-mail and temporary password through [Resend](https://resend.com).
   If e-mail isn't configured or fails, the user is still created, and the screen shows the
   password with a **Copiar** button so you can pass it on yourself.

At the first login with a temporary password, the app opens **"Crie sua senha"**, which can't be
skipped. Anyone can also change their password at any time in **☰ → Minha senha**. **"Esqueci
minha senha"** on the login screen sends Supabase's reset link.

## Setting it up (once)

### 1. Publish the function, choosing one way

**A. Supabase's web editor (no installs)**
1. Supabase → **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Name it exactly `admin-usuarios`.
3. Delete the example code, paste the whole content of
   [`functions/admin-usuarios/para-colar.ts`](functions/admin-usuarios/para-colar.ts), and click **Deploy**.
4. Open the function's **Details** tab, turn **off** "Verify JWT" (it may be called *Enforce JWT
   verification* or *Verify JWT with legacy secret*) and save. The function checks the login itself
   (it rejects anyone without a valid session). With this switch on, Supabase can block the app's
   calls before they reach the function, and the app then says it can't reach the function.
5. When this function changes in the repository later, paste the new `para-colar.ts` again.

**B. Automatic, from GitHub**
1. supabase.com → your avatar → **Account preferences → Access Tokens** → *Generate new token*.
2. GitHub → this repository → **Settings → Secrets and variables → Actions** → *New repository secret*,
   named `SUPABASE_ACCESS_TOKEN`.
3. GitHub → **Actions → Publicar funções do Supabase → Run workflow**. From then on, it publishes
   by itself whenever the function changes on `main`.

**C. Command line**: `npx supabase login`, then
`npx supabase functions deploy admin-usuarios --no-verify-jwt --project-ref yjpcjivkxvkvanzrhhnq`.

### 2. E-mail with the password (Resend)

1. Create an account at [resend.com](https://resend.com). Under **Domains**, add your domain (e.g.
   `kmd3market.com.br`) and create the DNS records it shows. Without your own domain, Resend
   only sends to your own address.
2. **API Keys → Create API Key** (*Sending access*).
3. Supabase → **Edge Functions → Secrets** (or *Project Settings → Edge Functions*), add:

| Name | Example |
|---|---|
| `RESEND_API_KEY` | `re_...` (the key from step 2) |
| `EMAIL_FROM` | `KMD3 Market <acesso@kmd3market.com.br>`, an address on the verified domain |
| `SITE_URL` | `https://kmd3market.vercel.app`, the app's address (goes in the e-mail) |

`SUPABASE_URL`, `SUPABASE_ANON_KEY` and `SUPABASE_SERVICE_ROLE_KEY` are provided by Supabase
automatically. You never copy the secret key anywhere.

### 3. "Esqueci minha senha" link (Supabase Auth)

- Supabase → **Authentication → URL Configuration**: set **Site URL** to the app's address and add
  it under **Redirect URLs**, so the reset link comes back to the app.
- Supabase's built-in e-mail only sends a few messages per hour. For a system with clients, set
  **Authentication → Emails → SMTP Settings** to Resend's SMTP (`smtp.resend.com`, port 465, user
  `resend`, password = the Resend API key). Then the reset e-mails also come from your domain.

## Testing that it works

Open **Administração**, choose the organization, fill in **Novo usuário** with your own second
e-mail and click **Criar usuário**. You should see *"Usuário criado. Enviamos a senha…"* and get the
e-mail. Log in with it: the app asks you to create a new password.

If the screen says *"A função admin-usuarios não foi encontrada"*, step 1 is missing, or the name isn't
exactly `admin-usuarios`. If it says it *can't reach the function* or that Supabase *refused the request*,
turn off "Verify JWT" (step 1, item 4); if it continues, check the function's **Logs** tab. If it
says the e-mail wasn't sent, step 2 is missing, or `EMAIL_FROM` isn't on a verified domain.
